# Blood Work Audit

A central lab supporting a clinical trial receives blood panels from many trial sites. When a specimen's integrity
score falls below the threshold, the patient's blood has to be drawn again. This app presents an audit answering:

> **Which sites have the highest redraw rates, and are there patterns in how their samples are collected or
> processed that might explain it?**

It shows:

- **Ranking:** the three sites with the highest repeat-draw rate in the review window, with counts and rates.
- **Findings:** for each ranked site, possible contributing factors (not established causes). Every claim cites the
  exact records behind it: a panel, its collection note, or a processing event.
- **Panel record sidebar:** click any citation and the cited record opens beside the findings, highlighted.
- **Panel explorer:** every panel for a site, filterable by date range and paginated.

The dataset is synthetic: 10,000 panels across 12 sites, with the audit's ranking and findings. The page is a display
for that data and its interactions; every cited record is checked against the data when the data is built.

## Stack

React 19, TypeScript, Vite, Tailwind CSS v4, shadcn/ui (Radix), TanStack Query and Table, react-three-fiber for the
3D red blood cell, Jest and React Testing Library.

## Run it

```bash
npm install
npm run dev       # local dev server
npm test          # unit tests
npm run build     # typecheck + production build into dist/
npm run preview   # serve the production build
```

The build uses a relative base (`./`), so `dist/` can be hosted from any sub-path, e.g. GitHub Pages.

## How the data is served

There is no backend. The UI's data hooks request `/api/manifest`, `/api/review`, `/api/panels` and
`/api/panels/:id`. An axios adapter (`src/api/staticGateway.ts`) answers them in the browser from static files in
`public/data/`, with filtering, stable paging and 404/422 errors like a real API.

`public/data/` is generated by `npm run data` (`scripts/build-data.mjs`) from the raw dataset in `source-data/`
(`manifest.json`, `panels.json`, `review.json`). That folder is not committed because of its size. The script:

- writes `summaries.json` (one row per panel, for the table) and `panels/<SITE>.json` (full records, fetched only
  when a panel is opened), so the page never downloads the whole 32 MB dataset;
- fails if any record the audit cites is missing from the data.
